# 功能清单与实施路线

标记：`[x]` 本轮原型实现；`[ ]` 尚未实现。

## P0 · 交互原型（本轮）

- [x] SwiftUI 原生窗口和菜单栏入口。
- [x] 四动作轮盘，点击或中心拖动选择。
- [x] 三种虚构渠道消息，切换演示项目/执行器。
- [x] 每个动作独立配置名称和纯文本提示词。
- [x] 确认卡，提示词快照编辑、补充说明和取消草稿。
- [x] 同目标重复 Ping 打开已有记录。
- [x] 确认后模拟提交，禁止同状态重复提交。
- [x] 模拟完成后显式补充并继续。
- [x] 原始消息、状态、逐轮推进记录持久化。
- [x] 原生 app 打包脚本与核心规则自检。
- [ ] 真实截图与全局覆盖层（P1）。
- [ ] 实机视觉验收和多屏手势验收（需要交互验证）。

## P1 · 真实桌面捕获

- [ ] 签名、权限说明、权限状态页。
- [ ] 全局快捷键与原生轮盘浮层，支持 Esc 和中心取消。
- [ ] 冻结目标窗口身份，排除自身覆盖层。
- [ ] ScreenCaptureKit 单次截图，多显示器与 Retina 坐标处理。
- [ ] AX / Vision 提取文字线索。
- [ ] 保存真实 Capture；仍先使用模拟执行器。

验收：目标识别不被浮层污染；不抢走原应用输入；空闲无持续截图。

## P2 · 微信 + Codex 闭环

- [ ] wxview 就绪、版本和缓存状态检测。
- [ ] 会话候选、消息锚点匹配、上下文读取与新鲜度说明。
- [ ] 明确绑定本地仓库；不根据聊天自动猜工作目录。
- [ ] Codex 适配器，提交、事件、续接和交互请求。
- [ ] SQLite、不可变 Submission、事务 outbox 和恢复流程。
- [ ] 验证外部会话如何打开，以及是否在已有客户端可见。

验收：一条真实消息到一次受控任务；重复 Ping 不创建重复任务；产物可回溯。
前置：解决或规避 wxview 高频发现开销，首版优先按需查询。

## P3 · 渠道和执行器扩展

- [ ] 飞书 user/bot 身份与权限、消息搜索及 thread。
- [ ] 钉钉组织绑定、消息查询与范围完整性。
- [ ] WorkBuddy 官方授权、本地助理可用性、提交与结果查询。
- [ ] 消息链接、附件、引用和截图降级处理。
- [ ] 不同消息归并同一任务的确认交互。

## P4 · 产品化

- [ ] 自定义槽位、图标、模板白名单变量、模板版本。
- [ ] 项目规则与默认执行器配置。
- [ ] 操作范围设置、证据保留策略、导出与删除。
- [ ] 自动更新、公证、分发与兼容性验证。
- [ ] 用户主动配置的自动交接策略。

## 暂不做

自研 Agent 推理框架、模型管理、全量聊天同步、常驻录屏、聊天平台自动回发、跨机器任务同步。

## 实测指标

空闲 CPU / 内存、Ping 到确认卡耗时、消息唯一匹配率、需人工选候选比例、重复派发次数、未知结果恢复率。

先建立实际基线，不以理论数值宣传包大小或延迟。
