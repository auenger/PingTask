## 自动检查

执行 `swift run PingTask --self-test`：

- 同来源/动作/项目/执行器生成相同意图键。
- 切换动作、项目、执行器生成不同键。
- 只有待确认状态允许首次提交。
- 执行中不能重复提交或继续。
- 完成后没有新增信息不能续接。
- 提示词和补充说明可以持久化往返。
- 不同 revision 生成不同 operationID。
- 使用隔离的临时存储验证真实 Store：重复捕获合并、保留编辑、双击提交不增加轮次。
- 重启恢复保留 operationID，未结束任务进入待核对。
- 修改模板不覆盖已有任务快照；新项目草稿采用新模板。
- 取消后再次捕获创建新草稿。

这些是规则及本地存储自检，不是 UI 自动化测试，也不验证真实平台幂等能力。测试使用临时目录，不读写用户的原型记录。

## 手工交互验收

1. 微信演示消息 → 分析一下：生成一条草稿。
2. 编辑提示词，再 Ping 同一动作：草稿数量不增加，编辑保留。
3. 确认提交：进入模拟执行中；再次 Ping 只打开原记录。
4. 约 1.5 秒后模拟完成，展示明确的模拟结果说明。
5. 不填新增信息时续接按钮不可用；填入新证据并确认后 revision 增加。
6. 同消息选择开始处理，或切换项目/执行器：新建独立草稿。
7. 在提示词设置页修改模板：旧记录快照不变；下一份新草稿使用新模板。
8. 取消草稿后再次 Ping：生成新草稿，不复活旧提交。
9. 重启：模板和记录保留。模拟执行期间退出后重启：标记待核对，不自动新建提交。
10. 从轮盘中心拖向四个方向；中心内松手不创建记录。

## 当前限制

- 演示入口仍为虚构消息；微信接入页可读本地缓存，飞书和钉钉尚未接入。
- 已实现全局 Alt / Ctrl 轮盘；真实跨应用手势仍需系统授权后验收。
- 三种演示消息的来源 ID 固定，不代表真实消息匹配已实现。
- 有 wxview CLI 与 ScreenCaptureKit 截图实现；没有外部网络和 Agent 调用。
- JSON 仅适用于单实例演示。多实例写入可能覆盖，不用于生产。
- 模拟执行中未结束的任务重启后仅展示待核对，核对恢复 UI 留待实际执行器集成。
- 手工视觉检查尚需在实际桌面完成；编译成功不等于布局已验收。

## 第一期 B 自动与视觉验证

新增隔离自检：Option 组合键取消/松手生命周期、中心死区与四方向、负坐标显示器转换、指针附近 OCR 门槛、同名会话歧义、来源未确认时禁止提交、确认后去重/编辑保留、Capture 持久化和显式截图降级。Vision 使用程序生成的文本图像检查实际 OCR 与指针映射，不读取真实桌面。

通过 `--render-wheel` 导出的四种合成轮盘状态已进行图像视觉检查：扇区、中心、动作标签、选中颜色和图标大小可见，已使用 lolPing 图标。该检查不覆盖动画、焦点或全局手势。

本机权限预检返回屏幕录制 false、辅助功能 false，因此真实屏幕截图、跨应用手势与微信内容端到端验收尚未执行。必须在打包的应用中授权后继续以下检查：

1. 在桌面 Ping 页授权、检查权限并启用。拒绝授权不得循环弹窗或后台截图。
2. 指向微信消息正文，按住 Option 并移动，检查四方向高亮；中心松手、Esc、右键均不新增捕获。
3. Option+字母/其他修饰键应取消手势，并保持原应用快捷键行为。
4. 松手后截图不含轮盘，原始窗口/指针正确；与截图中的橙圈及 OCR 线索核对。
5. 位于负坐标屏幕、Retina 和显示器边缘时检查轮盘可见、指针复位及截图对应关系。
6. 按住期间移动/关闭目标窗口，应显示失败，不误捕获其他窗口；轮盘不抢原应用输入。
7. 配好 wxview 后用唯一会话标题和消息正文自动检索；重名、无结果、媒体消息应保留歧义并允许手工修正。
8. 历史日期超出默认 30 天时调整范围；截断应显示总匹配数及实际返回数。
9. 来源待核对不能提交；确认重复消息打开已有记录，保留原编辑。仅截图草稿不得显示“已定位微信消息”。
10. 关闭主窗口后继续 Ping，应重新打开复核页；退出或重启不自动提交。
11. macOS 13 短时流首帧后停止；空闲没有录屏、OCR 或 wxview 轮询。

桌面 Ping 权限页通过隔离的原生离屏窗口生成预览并人工检查，按钮与文字布局正常。SwiftUI ImageRenderer 直接渲染 ScrollView 会得到空白，因此该页面预览改用 NSHostingView 的位图缓存；轮盘单独使用 ImageRenderer。未据此宣称真实屏幕权限或输入验收通过。

第一期 B 最终验证：Debug 编译、自检（包括真实 Vision 对合成图像的 OCR）、Release 打包、打包后二进制自检、codesign --verify --deep --strict、Info.plist 校验及 git diff --check 均通过。已通过 --desktop 启动打包应用并确认进程存活。打包二进制再次预检屏幕录制/辅助功能均为 false；实际全局输入、真实截图和微信端到端验证仍待授权，不能视为已验收。
