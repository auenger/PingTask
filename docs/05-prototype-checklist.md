# 原型验收

## 本轮验证结果

2026-10-20，本机 Intel macOS、Swift 6.2.3：

- Debug 编译与自检通过。
- Release 编译与打包后可执行文件自检通过。
- 本机 ad-hoc 签名校验、Info.plist 格式校验通过。
- `open dist/PingTask.app` 后确认应用进程存活。
- `.app` 本机磁盘占用约 628 KB，不含 CLI / Agent / 截图数据。
- 未进行人工视觉验收、真实全局输入、多屏和系统权限验证。

## 自动检查

执行 `swift run PingTask --self-test`：

- 同来源/动作/项目/执行器生成相同意图键。
- 切换动作、项目、执行器生成不同键。
- 只有待确认状态允许首次提交。
- 执行中不能重复提交或继续。
- 完成后没有新增信息不能续接。
- 提示词和补充说明可以持久化往返。
- 不同 revision 生成不同 operationID。
- 使用隔离的临时存储验证真实 Store：重复捕获合并、保留编辑、双击提交不增加轮次。
- 重启恢复保留 operationID，未结束任务进入待核对。
- 修改模板不覆盖已有任务快照；新项目草稿采用新模板。
- 取消后再次捕获创建新草稿。

这些是规则及本地存储自检，不是 UI 自动化测试，也不验证真实平台幂等能力。测试使用临时目录，不读写用户的原型记录。

## 手工交互验收

1. 微信演示消息 → 分析一下：生成一条草稿。
2. 编辑提示词，再 Ping 同一动作：草稿数量不增加，编辑保留。
3. 确认提交：进入模拟执行中；再次 Ping 只打开原记录。
4. 约 1.5 秒后模拟完成，展示明确的模拟结果说明。
5. 不填新增信息时续接按钮不可用；填入新证据并确认后 revision 增加。
6. 同消息选择开始处理，或切换项目/执行器：新建独立草稿。
7. 在提示词设置页修改模板：旧记录快照不变；下一份新草稿使用新模板。
8. 取消草稿后再次 Ping：生成新草稿，不复活旧提交。
9. 重启：模板和记录保留。模拟执行期间退出后重启：标记待核对，不自动新建提交。
10. 从轮盘中心拖向四个方向；中心内松手不创建记录。

## 当前限制

- 演示 UI 没有实际读取微信、飞书、钉钉；消息均为虚构。
- 仅窗口内手势，没有全局快捷键或跨应用轮盘。
- 三种演示消息的来源 ID 固定，不代表真实消息匹配已实现。
- 没有真实截图、CLI、外部网络和 Agent 调用。
- JSON 仅适用于单实例演示。多实例写入可能覆盖，不用于生产。
- 模拟执行中未结束的任务重启后仅展示待核对，核对恢复 UI 留待实际执行器集成。
- 手工视觉检查尚需在实际桌面完成；编译成功不等于布局已验收。
